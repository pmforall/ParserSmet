# Развёртывание и стандартный вход ЕКС

Браузерное приложение публикуется из двух файлов `dist/`. Исходники,
сметы, результаты тестов, архивы и отчёты не должны быть доступны веб-серверу.

Корпоративная интеграция использует отдельный OIDC-клиент `cii-smeta-parser`,
Authorization Code + S256 PKCE и собственную службу шлюза. Доступ определяется
стандартной авторизацией ЕКС. Сессии и cookie другого приложения не используются.

## Код в этом каталоге

- `prepare_sso.py` — проверка установленного шлюза и подготовка конфигураций.
- `stage_sso.py` — размещение проверенных неизменяемых файлов.
- `install_standalone.py` — первоначальная установка конфигурации своей службы.
- `register_idp_client.py`, `call_registration.py` — ограниченная регистрация
  собственного клиента через административный транспорт ЕКС.
- `activate_standalone.py` — проверка регистрации и собственного маршрута входа.
- `update_web.py` — обновление HTML и CSP с резервной копией и откатом.
- `box1_auth.py`, `activate_box1.py` — историческая схема общего входа,
  повторное включение которой заблокировано в коде.

Скрипты рассчитаны на управляемое окружение ЕКС и зависят от отдельно
установленного и проверенного пакета корпоративного шлюза. Адреса, пути,
идентификатор клиента и закреплённые хеши в коде — параметры этой интеграции,
а не секреты. Для другого окружения их необходимо согласованно настроить.

В архиве отсутствуют действующие конфигурации, ключи хранилища, client secret,
данные сессий, квитанции регистрации и доступ к корпоративному IdP. Эти данные
устанавливаются отдельно администратором из защищённого хранилища. Административные
права или доступ к серверу сам архив не предоставляет.

Изолированные тесты шлюза используют синтетический IdP. Они не выполняют вход
за реальных пользователей. Для производственных изменений необходимы резервная
копия, проверка текущих настроек, `nginx -t` и предусмотренный откат; изменения
должны ограничиваться собственной службой и маршрутом приложения.
